# Background reviews and measured findings — September 19, 2026

This release moves optional background reviews to durable Vercel Workflow jobs, tracks human decisions on findings, and replaces the main model leaderboard with confirmed outcomes. The five-model fixed council remains the default. Current curated prices and capabilities were refreshed from OpenRouter without silently replacing model IDs.

## Review execution

- Closing a tab or locking a phone does not stop a background job. History and Resume reconnect to its saved snapshot.
- Requests with identical active input are deduplicated. Each execution claims its workflow and each paid operation claims a lease before dispatch.
- Concurrent requests reserve cost under a PostgreSQL transaction lock. The ledger is read after the lock is acquired, preventing a stale joined snapshot from overwriting another worker's reservation or response.
- Stop prevents new reservations and cancels active requests. Completed answers and uncertain cost ceilings remain saved. An interrupted operation is not automatically sent again; retry requires an explicit resume.
- Client checkpoint routes cannot overwrite a background job's authoritative results or ledger.
- Provider credentials are encrypted with an independent server key and authenticated owner/run/execution binding. Workflow arguments and return values contain identifiers and orchestration metadata, not provider keys. Terminal jobs clear credentials; expired credentials cannot be used after 24 hours and the daily job removes remaining ciphertext.

## Finding decisions and citations

Findings can be marked open, accepted, dismissed (with an explicit reason), or fixed. Decisions and notes persist across reviews in the same project. Comparisons distinguish new, recurring, and not-reported findings. Absence is never treated as proof of a fix.

File/line links require an exact, unique quote in supplied source text. PR diffs retain head-side line numbers and a verified, immutable commit. Quotes spanning separate diff hunks, ambiguous occurrences, unsafe paths, and quotes taken only from model responses do not receive invented source links. Local or cached context without a verified commit is labeled supplied source and does not receive a misleading GitHub URL.

Model outcomes count human-confirmed accepted/fixed findings and explicitly dismissed false positives. Findings are deduplicated per project/model. Precision is withheld until five judged findings. Recorded costs include retries and uncertain reservations; synthesis-assigned attribution is observational and does not establish causal model superiority.

## Adaptive council and evaluation

Standard adaptive mode starts with three selected reviewers, preferring distinct families. It escalates to the remaining selected reviewers for high-impact findings, disagreement, unverified quotations, missing coverage, or insufficient completed reviewers. High-risk reviews use all selected reviewers. A second synthesis can make adaptive execution cost more than fixed execution; the same total spending limit applies.

The evaluator includes 20 cases, including 16 exact source excerpts from the real fixes between commits `a39d3480e2d5c5524e661fedb00c57f03251ef05` and `05c3f886be57c4ae83423dfc9d42fad35cc4aa1a`. Half are safe controls. Ground truth is limited to each case's stated contract. Invalid/truncated responses remain failures, unsupported claims count as false positives, and duplicates do not inflate useful findings. `--mode compare` evaluates fixed and adaptive councils with the same data and one shared budget.

The September 19 live smoke evaluation returned OpenRouter HTTP 402 (insufficient account credits), at $0 recorded spend. No live quality improvement or adaptive savings is claimed. The fixed roster was not changed on the strength of unrun benchmarks.

## Freshness and release checks

The daily authenticated Vercel cron checks all configured council, synthesis, enhancement and fallback roles, reports price/capability changes and release candidates on the Models page, and recovers stale jobs. Live catalog preflight still runs before a paid review. GitHub Actions remains blocked by an external account billing lock, so Vercel now runs lint, unit tests, a production dependency audit and the build before every deployment.

Dependencies use one canonical npm lockfile, verified with a clean Linux install. Scoped overrides patch the Workflow dependency tree without forcing incompatible major versions into unrelated dependencies. Bun is used only as the test runner.

## Account setup still required

Clerk provisioning requires the deployment owner to accept its provider terms. That step has not completed, so no placeholder login or unconfigured authentication SDK is shipped. The Marketplace skill requires: “If it needs the user's account or a dashboard/browser step → STOP and ask them to complete it, then continue.”

Existing private capabilities continue working. Unowned legacy reviews, telemetry, and hook jobs are no longer exposed anonymously, and are retained for an owner-verified migration once sign-in is provisioned. Stable accounts independent of provider-key rotation, and the legacy-to-account migration, remain pending; they are not represented as complete in this release.
